# 1장. 분석 기획과 분석 방법론
## 1. 분석 기획
### (1) 분석 기획의 정의와 특징
#### 분석 대상과 그 방법에 따른 4가지 분석 주제⭐⭐⭐
- 분석 대상이 무엇인지 앎 / 분석 방법 앎 -> 최적화(Optimization)
- 분석 대상이 무엇인지 앎 / 분석 방법 모름 -> 솔루션(Solution)
- 분석 대상이 무엇인지 모름 / 분석 방법 앎 -> 통찰(Insight)
- 분석 대상이 무엇인지 모름 / 분석 방법 모름 -> 발견(Discovery)
(*이해위한 표 추가 예정)

### (2) 목표 시점별 분석 기획 ⭐⭐ 🔖덜 중요
- **과제 단위(당면한 분석 주제 해결)**: **빠르게 해결**하는 목적
- **마스터플랜 단위(지속적 분석 문화 내재화)**: **지속적으로 문제를 분석**해 해결하는 것이 목적

### (3) 분석 기획 시 고려사항 ⭐⭐⭐ 🔖종종 출제, 안 어려우니 잘 읽기
- **가용 데이터 고려**: 분석의 기본인 **데이터가 확보될 수 있는지**
- 적절한 활용 방안과 **유스케이스의 탐색**: **기존에 잘 구현되어 활용되고 있는** 유사 시나리오 및 솔루션을 **최대한 활용**하는 것이 중요
- 장애요소에 대한 **사전 계획 수립**: 분석 수행시 발생 가능한 장애 요소에 대한 사전 계획 수립 필요
- 조직 역량 내제화


## 2. 분석 방법론 개요
### (1) 분석 방법론의 개요
#### 분석 방법론이란?
- 주어진 과제를 해결하기 위해 조직이 어떠한 절차로 작업을 수행해 나갈 것인지 일련의 절차를 정의한 것

#### 방법론 구성 요소 ⭐
- **절차**: 작업을 수행하기 위한 과정
- **방법**: 해당 절차를 수행하기 위한 방법 (예) 전문가에 자문을 구하거나 고객의 요구사항 파악을 위한 대면조사 등
- **도구와 기법**: 작업을 수행하는 데 필요한 것, 분석 수행 언어, 프로그램, 분석환경 등의 도구와 기법
- **템플릿**: 어떤 작업을 수행하기 위해 문서를 작성할 때 참고할 수 있는 일종의 양식
- **산출물**: 해당 작업이 종료된 이후 작성되는 문서 또는 프로그램

#### 기업의 합리적 의사 결정 방해요소 ⭐ 🔖아닌 것 고르기
- 고정관념
- 편향된 생각
- 프레이밍 효과: 동일한 사건이나 상황을 두고도 개인의 판단이나 선택이 달라질 수 있는 현상
  - (예) 물이 반 밖에 없네 / 물이 반이나 있네

#### 분석 방법론 생성 과정
- `방법론` -내재화-> `암묵지` -형식화-> `형식지` -체계화-> `방법론` -...-> (반복)


### (2) 분석 방법론이 적용되는 업무 특성에 따른 모델 ⭐⭐
#### 폭포수 모델
- 단계를 거쳐 순차적으로 진행하는 방법(Top-Down), 현재 단계가 완료되어야 다음 단계로 진행될 수 있다.
- 하지만 문제나 개선사항이 발견될 경우 이전 단계로 돌아가  피드백 과정을 수행할 수도 있음

#### 프로토타입 모델
- **일부분을 먼저 개발**하고, 그 이후 사용자의 요구분석, 정당성 점검, 성능 평가 등의 과정을 통한 개선 작업을 시행하며 **점진적으로 시스템을 개발**해 나가는 접근 방식

#### 나선형 모델
- **반복을 통해 점증적으로 개발** 하는 방식, 사용자의 요구에 초점을 맞추기 보다는 **위험요소를 사전에 제거하는 것에 초점을 맞춤**

#### 계층적 프로세스 모델
- 최상위에 큼지막한 몇 개의 단계가 구성 되어 있고, 그 하나의 단계는 여러 개의 태스크로 구성되고, 하나의 태스크는 여러 개의 스텝으로 구성되어 있다.
- 즉, 하나의 단계(Phase)는 태스크로, 하나의 태스크(Task)는 여러 개의 스텝(Step)으로 구성되어 있다.
- 스텝(WBS, Work Breakdown Structure)은 워크패키지이며, 입력(Input)-처리 및 도구(Process & Tool)-출력(Output)으로 구성된 단위 프로세스

#### 반복적 모델
- **증분적, 진화형으로 개발**하는 방식

#### 애자일
- **짧은 개발주기**를 가지고 **지속적으로 피드백을 반영**해나가며 **반복 개발**하는 방식


## 3. 전통적인 분석 방법론 두 가지 
🔖외우기, 두 방법론의 차이점 알기
### (1) KDD 분석 방법론 ⭐
- KDD(Knowledge Discovery in Database)는 데이터로부터 통계적 패턴이나 지식을 찾기위해 체계적으로 정리한 **데이터 마이닝 프로세스**(전통적)
- 데이터셋 **선택** -> 데이터 **전처리** -> 데이터 **변환** -> 데이터 **마이닝** -> 해석과 **평가**

### (2) CRISP-DM 분석 방법론 ⭐⭐
- CRISP-DM(Cross Industty Standard Process for Data Mining)은 KDD와 비슷하지만 더 세분화된 분석 방법론이다.
- 단계, 일반화 태스크, 세분화 태스크, 프로세스 실행의 4개의 레벨과 업무 이해, 데이터 이해, 데이터 준비, 모델링, 평가 , 전개의 6단계로 구성되어 있다.(다른 방법론은 3단계)
- ⭐**업무 이해**⭐ -> 데이터 **이해** -> 데이터 **준비** -> **모델링** -> **평가** -> **전개** 🔖업데데이트모델평가전개

#### SEMMA
- Sample -> Explore -> Modify -> Model -> Assess


## 4. 빅데이터 분석 방법론 
🔖시험에 자주 등장, 단계별 수행 내용, 태스크로 이어지는 프로세스 꼭 알기
### (1) 빅데이터 분석 방법론 개요 
- 완벽한 계층적 프로세스 모델로서 단계, 태스크, 스텝의 3계층 레벨과 5단계로 구성되어 있다.
- 5개의 단계를 프로세스 그룹이라고 하며, 각 단계는 여러개의 태스크로 구성되고, 각 태스크는 물리적 또는 논리적으로 품질 검토의 항복이 될 수 있다.
