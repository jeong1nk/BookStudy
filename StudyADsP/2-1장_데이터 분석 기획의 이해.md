# 1장. 분석 기획과 분석 방법론
## 1. 분석 기획
### (1) 분석 기획의 정의와 특징
#### 분석 대상과 그 방법에 따른 4가지 분석 주제⭐⭐⭐
- 분석 대상이 무엇인지 앎 / 분석 방법 앎 -> 최적화(Optimization)
- 분석 대상이 무엇인지 앎 / 분석 방법 모름 -> 솔루션(Solution)
- 분석 대상이 무엇인지 모름 / 분석 방법 앎 -> 통찰(Insight)
- 분석 대상이 무엇인지 모름 / 분석 방법 모름 -> 발견(Discovery)
(*이해위한 표 추가 예정)

### (2) 목표 시점별 분석 기획 ⭐⭐ 🔖덜 중요
- **과제 단위(당면한 분석 주제 해결)**: **빠르게 해결**하는 목적
- **마스터플랜 단위(지속적 분석 문화 내재화)**: **지속적으로 문제를 분석**해 해결하는 것이 목적

### (3) 분석 기획 시 고려사항 ⭐⭐⭐ 🔖종종 출제, 안 어려우니 잘 읽기
- **가용 데이터 고려**: 분석의 기본인 **데이터가 확보될 수 있는지**
- 적절한 활용 방안과 **유스케이스의 탐색**: **기존에 잘 구현되어 활용되고 있는** 유사 시나리오 및 솔루션을 **최대한 활용**하는 것이 중요
- 장애요소에 대한 **사전 계획 수립**: 분석 수행시 발생 가능한 장애 요소에 대한 사전 계획 수립 필요
- 조직 역량 내제화


## 2. 분석 방법론 개요
### (1) 분석 방법론의 개요
#### 분석 방법론이란?
- 주어진 과제를 해결하기 위해 조직이 어떠한 절차로 작업을 수행해 나갈 것인지 일련의 절차를 정의한 것

#### 방법론 구성 요소 ⭐
- **절차**: 작업을 수행하기 위한 과정
- **방법**: 해당 절차를 수행하기 위한 방법 (예) 전문가에 자문을 구하거나 고객의 요구사항 파악을 위한 대면조사 등
- **도구와 기법**: 작업을 수행하는 데 필요한 것, 분석 수행 언어, 프로그램, 분석환경 등의 도구와 기법
- **템플릿**: 어떤 작업을 수행하기 위해 문서를 작성할 때 참고할 수 있는 일종의 양식
- **산출물**: 해당 작업이 종료된 이후 작성되는 문서 또는 프로그램

#### 기업의 합리적 의사 결정 방해요소 ⭐ 🔖아닌 것 고르기
- 고정관념
- 편향된 생각
- 프레이밍 효과: 동일한 사건이나 상황을 두고도 개인의 판단이나 선택이 달라질 수 있는 현상
  - (예) 물이 반 밖에 없네 / 물이 반이나 있네

#### 분석 방법론 생성 과정
- `방법론` -내재화-> `암묵지` -형식화-> `형식지` -체계화-> `방법론` -...-> (반복)


### (2) 분석 방법론이 적용되는 업무 특성에 따른 모델 ⭐⭐
#### 폭포수 모델
- 단계를 거쳐 순차적으로 진행하는 방법(Top-Down), 현재 단계가 완료되어야 다음 단계로 진행될 수 있다.
- 하지만 문제나 개선사항이 발견될 경우 이전 단계로 돌아가  피드백 과정을 수행할 수도 있음

#### 프로토타입 모델
- **일부분을 먼저 개발**하고, 그 이후 사용자의 요구분석, 정당성 점검, 성능 평가 등의 과정을 통한 개선 작업을 시행하며 **점진적으로 시스템을 개발**해 나가는 접근 방식

#### 나선형 모델
- **반복을 통해 점증적으로 개발** 하는 방식, 사용자의 요구에 초점을 맞추기 보다는 **위험요소를 사전에 제거하는 것에 초점을 맞춤**

#### 계층적 프로세스 모델
- 최상위에 큼지막한 몇 개의 단계가 구성 되어 있고, 그 하나의 단계는 여러 개의 태스크로 구성되고, 하나의 태스크는 여러 개의 스텝으로 구성되어 있다.
- 즉, 하나의 단계(Phase)는 태스크로, 하나의 태스크(Task)는 여러 개의 스텝(Step)으로 구성되어 있다.
- 스텝(WBS, Work Breakdown Structure)은 워크패키지이며, 입력(Input)-처리 및 도구(Process & Tool)-출력(Output)으로 구성된 단위 프로세스

#### 반복적 모델
- **증분적, 진화형으로 개발**하는 방식

#### 애자일
- **짧은 개발주기**를 가지고 **지속적으로 피드백을 반영**해나가며 **반복 개발**하는 방식


## 3. 전통적인 분석 방법론 두 가지 
🔖외우기, 두 방법론의 차이점 알기
### (1) KDD 분석 방법론 ⭐
- KDD(Knowledge Discovery in Database)는 데이터로부터 통계적 패턴이나 지식을 찾기위해 체계적으로 정리한 **데이터 마이닝 프로세스**(전통적)
- 데이터셋 **선택** -> 데이터 **전처리** -> 데이터 **변환** -> 데이터 **마이닝** -> 해석과 **평가**

### (2) CRISP-DM 분석 방법론 ⭐⭐
- CRISP-DM(Cross Industty Standard Process for Data Mining)은 KDD와 비슷하지만 더 세분화된 분석 방법론이다.
- 단계, 일반화 태스크, 세분화 태스크, 프로세스 실행의 4개의 레벨과 업무 이해, 데이터 이해, 데이터 준비, 모델링, 평가 , 전개의 6단계로 구성되어 있다.(다른 방법론은 3단계)
- ⭐**업무 이해**⭐ -> 데이터 **이해** -> 데이터 **준비** -> **모델링** -> **평가** -> **전개** 🔖업데데이트모델평가전개

#### SEMMA
- Sample -> Explore -> Modify -> Model -> Assess


## 4. 빅데이터 분석 방법론

### (1) 빅데이터 분석 방법론 개요 
- 완벽한 계층적 프로세스 모델로서 단계, 태스크, 스텝의 3계층 레벨과 5단계로 구성되어 있다.
- 5개의 단계를 프로세스 그룹이라고 하며, 각 단계는 여러개의 태스크로 구성되며 이는 매핑이라고 한다. 또, 각 태스크는 여러 개의 스텝으로 구성되어 있으며 이는 유닛 프로세스라고 한다.

# 2장. 분석 과제 발굴
## 1. 분석 과제 발굴 개요
### (1) 분석 과제 탐색 방법 ⭐⭐⭐ 🔖상향식 하향식!!
- **하향식 접근법**: **전통적인 Top-Down** 수행 방법으로, 각 과정이 체계적으로 단계화되어 문제를 해결하는 방식 🔖주제 먼저
- **상향식 접근법**: 대규모 데이터가 생성되고 빠르게 변하는 현대에서는 문제가 무엇인지 사전에 정의하는 것이 어렵다. 따라서 다양한 데이터의 조합 속에서 인사이트를 찾아내는 **Bottom-Up** 방식이다. 🔖데이터 먼저
- 분석의 대상을 알고 있다면 하향식, 모른다면 상향식 접근법을 사용한다.

### (2) 분석 과제 발굴

### (3) 분석 과제 발굴 방법론 개념도⭐ 🔖출제 가능성 높! 특히 하향식 접근법의 단계별 내용
- "분석의 대상이 무엇인지 알고 있는가?" -> YES [하향식 접근법]
  1. 문제 탐색 단계⭐⭐ 🔖여기서 많이 나옴! "STEEP"-사회/기술/경제/환경/정치
     - 비즈니스 모델 탐색 기법(지원인프라, 업무, 고객, 제품, 규제와 감사)
     - 분석기회 발굴 및 범위 확장
     - 외부 참조 모델  기반 문제 탐색
     - 분석 유스케이스
  2. 문제 정의 단계
     - 식별된 비즈니스 문제를 데이터 문제로 변환하여 과제를 정의
  3. 해결 방안 탐색 단계

#### 2. 분석 기회 발굴 범위의 확장 ⭐⭐
**1. 거시적 관점**
- 문제 혹은 변화가 기업에 주는 영향을 탐색
  - 사회: 노령화 문제, 저출산 문제 등
  - 기술: 나노 기술, IT 융합 기술, 로봇 기술의 등장 등
  - 경제: 원자제 가격, 환율, 금리의 변화 등
  - 환경: 탄소 배출 규제 등
  - 정치: 대북 관계 등
**2. 경쟁자 확대 관점**
- 기업에 위협이 될 상황을 탐색
  - 대체재: 기업의 상품 및 서비스가 대체될 수 있는 것에 대한 탐색 및 잠재적 위협 파악
  - 경쟁자: 식별된 주요 경쟁사의 제품 및 서비스 카탈로그 및 전략을 분석
  - 신규 진입자: 현재 직접적인 경쟁자는 아니지만 향후 영향력이 커질 것으로 판단되는 위협
**3. 시장의 니즈 탐색**
- 시장의 니즈 탐색 관점에서 문제를 탐색
  - 고객: 고객 기업들의 산업 및 경영 현황 등을 파악
  - 채널: 상품 및 서비스가 전달될 수 있는 경로에 대한 파악
  - 영향자들: 시장 확대에 따른 유사 업종의 기업 인수 등에 대한 파악
**4. 역량의 재해석**
- 역량의 재해석 관점에서 다시 기업 내부를 둘러보도록 함.
  - 내부 역량: 자사 소유 부동산 등 부가 가치 창출의 기회 캄색
  - 파트너와 네트워크: 자사가 직접 보유하고 있는 않지만 관계사 혹은 공급사의 역량을 활용한 부가가치 창출 기회의 탐색으로 기업 경영 노하우 등이 있음 

#### 3. 외부 참조 모델 기반 문제 탐색 및 분석 유스케이스 정의
- 유사 동종 업계에서 기존에 수행한 문제 탐색 및 분석 과제 등을 활용하는 것(벤치마킹) 역시 중요한 시사점을 도출함
- 현재 비즈니스 모델 및 유사, 동종 업계의 탐색을 통해 발견된 문제들을 세부과제로 도출하기 전에 먼저 '분석 유스케이스(Analytics Use Case)'로 정의함. 그 이후 어떻게 풀어나갈지 등에 대해 명시
- 분석 유스케이스란, 분석을 적용했을 때 업무 흐름을 개념적으로 설명한 것으로 프로세스 혁신 수단으로 활용되기도 함.

- (예) 영업 부서 "최근 고객들의 불만이 높아지고 있다."(비즈니스 문제) -> 데이터의 분제로 변환 "고객의 불만에 영향을 끼치는 요인은 무엇인지 분석하고, 그 요인과 고객 불만율에 대한 상관 및 예측 모델을 수립한다."

### (3) 3단계-해결 방안 탐색 단계
#### 해결 방안 탐색
- 문제 정의 단계에서 정의된 데이터 분석 문제를 해결하기 위한 방안을 모색하는 단계.
- 기존 시스템으로 가능
  - 분석 역량이 있다 -> 기존 시스템과 인력으로 수행
  - 분석 역량이 없다 -> 역량을 확보(교육&채용)
- 기존 시스템으로 불가능
  - 분석 역량이 있다 -> 시스템 고도화
  - 분석 역량이 없다 -> 전문업체 아웃소싱

### (4) 4단계-타당성 검토 단계
#### 타당성 검토
- 수행되어야 할 분석 과제가 정의되었고 어떤 방법으로 어떤 인력과 함께 수행될지 결정되었다면 이 방안이 타당한 것인지 검토해야 한다.
- 타당성 검토는 크게 경제적 타당성 검토와 데이터 및 기술적 타당성 검토로 나뉜다.

#### 상향식 접근법 개념
- 분석 대상이 무엇인지 모를 경우 **먼저 분석부터 시작해 그 결과로부터 가치가 있는 문제를 도출**하는 분석 과제 발굴을 위해 사용하는 방법. 원천 데이터로부터 통찰과 지식을 얻는 접근 방법.
- 앞서 살펴본 스탠퍼드 대학 d.school의 디자인 씽킹이 해당된다.
- (예) 100가지의 물감 -> 원하는 색을 찾기 위해 색의 선택과 그 비율을 무수히 많이 시도할 수 있음

### (2) 지도학습과 비지도학습⭐⭐⭐ 🔖너무너무 중요!
#### 1. 지도학습 🔖대부분의 인공지능이 다 지도학습
- **정답이 있는 데이터를 활용해 분석 모델을 학습시키는 것**
- 레이블이 범주형인 분류와 연속형인 회귀로 나누어 짐.
- (예) 머신러닝, 의사결정 트리, 인공신경망 모형, 분류 분석

#### 2. 비지도학습
- **정답을 알려주지 않고 학습하는 것**
- 정답 레이블이 없는 데이터를 비슷한 특징을 가진 데이터끼지 군집화해 새로운 데이터에 대한 결과를 예측(스스로 학습하기 때문에 덜 정확적)
- 목적이 명확히 정의된 특정 필드의 값을 구하는 것이 아닌, 데이터 자체의 결합, 연관성, 유사성 등을 중심으로 데이터의 상태를 표현하는 것.
- 일반적으로 상향식 접근방식의 데이터 분석은 비지도학습에 의해 수행
- (예) 장바구니 분석, 기술통계, 프로파일링, 군집 분석, 주성분분석, 다차원 척도 🔖정답이 애초에 없다.

### (3) 시행착오를 통한 문제 해결(프로토타이핑 접근법)⭐⭐⭐
#### 1. 개념
- 상향식 접근법 중 하나로 시행착오 해결법이라고도 함.
- 먼저 분석을 시도하고 그 결과를 확인하면서 조금씩 개선해나가는 방법 🔖일단 만들고 디벨롭
- 문제 정의가 불명확하고 새로운 문제일 경우 빅데이터 분석 환경에서 오히려  프로토타이밍 접근법이 더 유용하다.

#### 2. 프로세스
- 가설의 생성 -> 디자인에 대한 실험 -> 실제환경에서의 테스트 -> 테스트 결과로부터 인사이트 도출 및 가설 확인

#### 3. 프로토타이핑 접근법이 필요한 경우
- 문제에 대한 인식 수준이 낮거나 불명확한 경우
- 필요 데이터의 존재 여부가 불확실할 경우
- 데이터의 사용 목적이 고정되지 않고 변화할 경우


# 3장. 분석 프로젝트 관리 방안
## 1. 분석 프로젝트 관리 개요
### (1) 분석 과제를 관리할 때 고려해야 할 5가지 속성⭐
1. 데이터의 양
2. 데이터 복잡도
3. 분석의 속도
4. 분석 복잡도
- 분석 모델의 정확도와 해석력을 트레이드오프 관계
- 복잡도가 올라갈수록 정확도가 올라가지만 해석이 어려움. 즉, 모델 정확도가 높으면서 해석이 편리한 최적의 모델 탐색 필요.
5. 정확도 & 정밀도⭐
- 정확도(Accuracy): 모델과 실제 값 간의 차이가 적다는 것을 의미
- 정밀도(Precision): 반복적으로 모델을 사용했을 때 모델 값들의 편차 수준
- 정확도와 정밀도는 트레이드 오프 관계이다.
(이해를 위한 그림 첨부 필요)

## 2. 분석 과제 관리 방안

### 능력 성숙도 통합 모델(CMMI)⭐⭐
- 소프트웨어 및 시스템 공학의 역량 성숙도를 파악하기 위한 모델로서 5단계로 나눠서 역량을 평가함.
  - 1단계: 개인의 역량이 프로젝트의 성공과 실패를 나누는 주요 요인으로 프로젝트 개발 프로세스가 거의 없다.
  - 2단계: 일정이나 비용과 같은 요소가 프로세스의 중심으로, 약간의 개발 프로세스하에서 통제되는 상태.
  - 3단계: 2단계에서 존재하지 않는 조직을 관리하기 위한 프로세스가 존재하는 상태.
  - 4단계: 체계적인 관리하에 프로젝트 및 산출물에 대한 정량적인 측정이 가능한 상태
  - 5단계: 조직적으로 최적화된 프로세스를 보유하고 지속적인 개선을 목표로 하는 상태
