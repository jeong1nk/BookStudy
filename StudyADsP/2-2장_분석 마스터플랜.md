# 1. 마스터플랜 수립
## 1. 마스터플랜 수립
### 분석 마스터플랜 수립 프레임워크⭐⭐⭐ 🔖굵은 부분 구분하기
- 분석 과제의 우선 순위를 결정하고 기업의 상황을 고려해 분석 과제의 적용 범위 및 방식을 결정하여 분석 구현 로드맵을 수립함.
- 분석 마스터 플랜을 수립하는 가장 첫 단추는, 발굴한 분석 과제의 우선순위를 정하는 것.
- **우선 순위는 [전략적 중요도], [비즈니스 성과/ROI], [실행 용이성]을 기준**으로 우선 순위를 설정한다.
- **적용 범위/방식은 [업무 내재화 적용 수준], [분석 데이터 적용 수준], [기술 적용 수준]를 기준**으로 분석 구현 로드맵을 수립한다.

## 2. 수행 과제 도출 및 우선 순위 평가
### (1) 일반적인 IT 프로젝트 우선순위 평가⭐⭐
- 전략적 중요도와 실행 용이성 두가지를 기준으로 우선 순위 기준을 수립해 평가한다.
- **전략적 중요도**
  - 전략적 필요성
    - 전략적 목표 및 복원적 업무에 직접적인 연관관계 밀접한 정도
    - 이슈 미해결 시 발생할 위험 및 손실에 대한 정도
  - 시급성
    - 사용자 요구사항, 업무능률 향상을 위해 시급히 수행되어야 하는지에 대한 정도
    - 향후 경쟁우위 확보를 위한 중요성 정도 
- **실행 용이성**
  - 투자 용이성
    - 기간 및 인력 투입 용이성 정도
    - 비용 및 투자예산 확보 가능성 정도
  - 기술 용이성
    - 적용 기술의 안정성 검증 정도
    - 응용 시스템, H/W 유지보수 용이성 정도
    - 개발 스킬 성숙도 및 신기술 적용성 정도

### (2) 빅데이터의 특징을 고려한 분석 ROI 요소⭐⭐
- 빅데이터의 특징인 4V를 관점으로, 크게 투자 비용 요소와 비즈니스 효과 요소가 있다.
- **투자 비용 요소(Investment)** 🔖3V
  - 크기(Volume): 데이터 규모/양
  - 다양성(Variety): 데이터 종류/유형
  - 속도(Velocity): 데이터 생성속도/처리속도
- **비즈니스 효과 요소(Return)** 🔖Value(가치)
  - **가치(Value)**: 분석 결과 활용 및 실행을 통한 비즈니스 가치

### (3) ROI를 활용한 우선순위 평가 기준⭐⭐
- 먼저 전략적 중요도에 따른 시급성을 판단한 후, 난이도를 살펴본다.
- 시급성의 판단 기준: 전략적 중요도(기여도)(현재, 미래 중 어디에 관점을 둘지), 목표가치(KPI)
- 난이도의 판단 기준: 데이터 획득/저장/가공 비용, 분석 적용 비용, 분석 수준
- 🔖이 때, **시급성은 Value에 난이도는 3V에 해당된다. Value가 가장 중요하므로 시급성 또한 가장 중요**하다.

### (4)  포트폴리오 사분면(Quadrant) 분석을 활용한 우선순위 평가 기준⭐⭐ 🔖논란이 있었어서 잘 안나오긴 함
- 난이도와 시급성을 동시에 고려해 판단한다.
(이해를 위한 그림 첨부 예정)
- 시급성 중요: 3->4->2
- 난이도 중요: 3->1->2

#### 마스터 플랜과 ISP 🔖읽고 이해
- 마스터 플랜: 정보시스템 마스터플랜(ISMP, Information System Master Plan)에서 나온 단어로, 특정 SW 개발 사업에 대한 상세분석과 제안 요청서를 마련하기 위해 비즈니스 및 정보기술에 대한 현황과 요구사항을 분석하고 구축 전략 및 이행 계획을 수립하는 활동, 즉, 하나의 정보시스템 구축 중심의 개념
- ISP(Information Strategy Planning): 조직 전체의 경영목표 전략을 효과적으로 지원하기 위한 정보화전략 및 비전을 정의하고 IT사업과제 도출 및 로드맵을 수립하는 활동


## 3. 이행 계획 수립
### (1) 로드맵 수립
- 포트폴리오 사분면 분석을 통한 우선순위 결정 -> 과제별 적용 범위 및 방식을 고려한 최종 우선순위 결정 ->  단계적 구현 로드맵을 수립 -> 단계별로 추진 목표 정의 -> 추진 과제별 선후행 관계를 고려해 추진 내용 정렬

### (2) 세부 이행 계획 수립
- 고전적인 폭포수 방식보다는 프로토타입과 같이 반복적인 모델링 과정을 수행해 프로젝트의 완성도를 높이는 방식이 권장됨.
- 그러나 모든 단계를 반복하기보다 모델링 단계를 반복적으로 수행하는 혼합형(Analytics)을 많이 적용함.


# 2. 분석 거버넌스 체계 수립
## 1. 거버넌스 체계 개요
### (1) 분석 거버넌스 체계 개요
- 거버넌스(Governance): '통치'란 뜻으로, 기업엣 ㅓ의사결정을 위한 데이터의 분석과 활용을 위한 체계적인 관리를 의미
- 어떤 목적으로 어떤 분석을 수행하고, 어떻게 데이터를 활용할지 결정하고, 데이터 분석을 기업의 문화로 정착시키고 데이터 분석 업무를 지속적으로 고도화하기 위해 데이터 관리 체계를 수립하는 것

### (2) 분석 거버넌스 체계 구성 요소⭐ 🔖가끔 나옴, 앞글자 따서 기억 "시조프로마인드데"
- 분석 관련 **시**스템(System)
- **조**직(Organiztion): 분석 기획 및 관리를 수행
- 과제 기획 및 운영 **프로**세스(Process)
- 분석 관련 교육 및 **마인드** 육성 체계(Human Resource)
- **데**이터(Data)

## 2. 데이터 분석 성숙도 모델 및 수준 진단 
### (1) 분석 수준 진단 프레임 워크
- 분석 준비도와 분석 성숙도를 통해 데이터 분석 수준을 진단하고 데이터 분석 기반을 구현하기 위해 무엇을 준비하고 보완해야 하는지 등 분석의 유형 및 분석의 반향성을 결정할 수 있다.

### (2) 분석 준비도⭐⭐⭐ 🔖세부내용까지 외워야함! "IT문데기인파"
- **IT 인프라**
  - 운영 시스템 데이터 통합
  - EAI, ETL 등 데이터 유통체계
  - 분석  전용 서버 및 스토리지
  - 빅데이터/통계/비주얼 분석환경
- **분석 문화**
  - 사실에 근거한 의사 결정
  - 관리자의 데이터 중시
  - 회의 등에서 데이터 활용
  - 경영진 직관보다 데이터 활용
  - 데이터 공유 및 협업 문화
- **분석 데이터**
  - 분석 업무를 위한 데이터
  - 충분성/신뢰석/적시성
  - 비구조적 데이터 관리
  - 외부데이터 활용 체계
  - 기준 데이터 관리(MDM)
- **분석 기법**
  - 업무별 적합한 분석 기법 사용
  - 분석 업무 도입 방법론
  - 분석 기법 라이브러리

  - 분석 기법 정기적 개성
- **분석 인력 및 조직**
  - 분석전문가 직부 존재
  - 분석전문가 교육 훈련프로그램
  - 관리자 기본 분석 능력
  - 전사촌괄조직
  - 경영진 분석 업무 이해
- **분석 업무 파악**
  - 발생한 사실 분석 업무
  - 예측 분석 업무
  - 시뮬레이션 분석 업무
  - 최적화 분석 업무
  - 분석 업무 정기적 개선

## 4. 데이터 거버넌스 체계 수립
### (1) 데이터 거버넌스 구성 요소
- 데이터 거버넌스: 전사 차원의 모든 데이터에 대해 정책 및 지침, 표준화, 운영조직 및 책임 등의 표준화된 관리 체계를 수립하고 운영을 위한 프레임워크 및 저장소를 구축하는 것
- 데이터 거버넌스의 중요한 관리 대상: **마스터 데이터, 메타 데이터, 데이터 사전**
- 데이터 거버넌스 구성 요소 🔖"원조프"
  - **원칙(Principle)**: 데이터를 유지 관리하기 위한 지침과 가이드
    (예) 보안 & 품질 기준, 변경 관리 
  - **조직(Organization)**: 데이터를 관리할 조직의 역할과 책임
    (예) 데이터 관리자, DB 관리자, 데이터 아키텍트
  - **프로세스(Process)**: 데이터 관리를 위한 활동과 체
    (예) 작업 절차, 모니터링 활동, 측정 활동

### (2) 데이터 거버넌스 체계
#### 1. 데이터 표준화 
- 데이터 표준화: 데이터 표준 용어 설정, **명명 규칙(Name Rule)** 수립, **메타데이터** 구축, **데이터 사전** 구축 등의 업무로 구성된다.

#### 2. 데이터 관리 체계
- 데이터 적합성 및 활용의 효율성을 위해 표준 데이터를 포함한 메타데이터와 데이터 사전의 관리 원칙을 수립한다.
- 빅데이터의 경우 데이터 양의 급증으로 **데이터의 생명 주기 관리 방안**을 수립하지 않으면 데이터 가용성 및 관리 비용 증대 문제에 직면할 수도 있다.

#### 3. 데이터 저장소 관리(Repository)
- 메타데이터 및 표준 데이터를 관리하기 위한 전사 차원의 저장소를 구성한다.
- 저장소는 데이터 관리 체계 지원을 위한 워크플로 및 관리용 응용 소프트웨어를 지원하고 관리 대상 시스템과의 인터페이스를 통한 통제가 이루어져야 하며, 데이터 구조 변경에 따른 사전 영향 평가도 수행돼야 효율적인 활용이 가능하다.

#### 4. 표준화 활동
- 데이터 거버넌스 체계를 구축한 후 표준 준수 여부를 주기적으로 점검하고 모니터링을 실시한다.
- 지속적인 데이터 표준화 개선 활동을 통해 실용성을 높여야 한다.

## 5. 데이터 조직 및 인력방안 수립
### (1) 데이터 분석 조직 및 인력방안 개요
#### 1. 데이터 분석 조직
- 분석 조직은 기업 내에 존재하는 빅데이터 속에서 가치를 찾아 전파하고 이를 행동화하는 역할을 한다.
  - 목표: 기업의 경갱력 확보를 위해 비즈니스 질무놔 이에 부합하는 가치를 찾고 비즈니스를 최적화하는 것
  - 역할: 전사 및 부서의 분석 업무를 발굴하고 전문적 기법과 분석 도구를 활용해 기업 내 존재하는 빅데이터 속에서 인사이트를 찾아 전파하고 이를 액션화 하는 것
  - 구성: 기초 통계학 및 분석 방법에 대한 지식과 분석 경험을 보유하고 있는 인력으로 전사 또는 부서 내 조직으로 구성하여 운영

#### 2. 데이터 분석 조직 유형⭐⭐⭐ 🔖자주 나옴!! "집기분" 어떤게 집기분인지 차이점 제대로 알기
(이해를 위한 그림 첨부 예정)
- **집중형 조직 구조**
  - 조직 내에 별도의 독립적인 분석 점담 조직을 구성하고, 회사의 모든 분석 업무를 전담 조직에서 담당
  - 분석 전담 조직 내부에서 전사 분석 과제의 전략적인 중요도에 다라 우선순위를 정해 추진할 수 있다.(장점)
  - 일부 현업 부서와 분석 업무가 중복 또는 이원화될 가능성이 있음.(단점)
- **기능 중심의 조직 구조**
  - 일반적으로 분석을 수행하는 형태이며, 별도로 분석 조직을 구성하지 않고 각 해당 업무 부서에서 직접 분석하는 형태
  - 전사적 관점에서 핵심 분석이 어려우며, 특정 업무부서에 국한된 분석을 수행할 가능성이 높거나 이원화 발생 또는 일부 중복된 분석 업무를 수행할 수 있음.(단점) 
- **분산형 조직 구조**
  - 분석 조직의 인력을 현업 부서에 배치해 분석 업무를 수행하는 형태
  - 전사 차원에서 분석  과제의우선순위를 선정해 수행이 가능하며, 분석 결과를 신속하게 실무에 적용 가능하다.(장점)

## 6. 분석 과제 관리 프로세스 수립
(이해를 위한 표 첨부 필요)⭐⭐
- 도출된 분석 과제들을 체계적으로 관리하기 위한 프로세스가 요구된다.
- 분석 과제 관리 프로세스는 크게 과제 발굴과 과제 수행으로 나뉜다.
- **과제 발굴**: 개별 조직 혹은 개인이 과제를 발굴하고 이를 과제화해 POOL(사용 가능한 데이터의 집합)로 관리하고 분석 과제를 선정함
- **과제 수행**: 선정된 과제에 대해 팀을 구성하고 분석 과제를 수행하면서 지속적인 모니터링 작업을 변행하고 그 결과를 공유 및 개선하는 절차

## 7. 분석 교육 및 변화 관리
### (1) 분석 교육 및 변화관리의 개요
- 기업과 경영층은 변화관리를 지속적으로 계획하고 수행해야 하며, 적합한 분석 업무를 도출하고 가치를 높일 수 있도록 지속적인 교육과 훈련을 실시해야한다.

### (2) 분석 도입에 대한 문화적 대응⭐
(이해를 위한 그림 첨부 필요)
- 과거: 분석 업무는 기업의 분석가가 담당, 현재: 모든 구성원이 데이터를 분석해 이를 업무에 즉시 활용할 수 있도록 하려함
- 하지만 새로운 체계가 도입되는 만큼 **과거로 돌아가려는 관성 또한 존재**하기 때문에 변화관리가 필요함.

### (3) 분석 교육
- 단순한 데이터 분석 툴(R, Python, SAS 등) 교육이 아닌 분서 ㄱ역량 확보 및 강화에 초점을 맞추어야 한다.
- 분석 기획자: 데이터 분석 큐레이션 교육, 분석 실부자: 데이터 분석 기법 및 도구, 업무 수행자: 분석 기획 발굴 및 시나리오 작성법 등의 교육을 통해 조직 구성원 모두에게 분석 기반 업무를 정착시킬 수 있어야 한다.
